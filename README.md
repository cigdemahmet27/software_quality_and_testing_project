## Overview

This project evaluates LLM-based code and test generation using the [HumanEval-X Java dataset](https://github.com/zai-org/CodeGeeX/tree/main/codegeex/benchmark/humaneval-x/java/data). We use two LLMs in a **semi-agentic approach** to generate Java code and unit tests, then assess quality through coverage analysis, test smell detection, and black-box testing techniques.

## Approach

- **Type:** Semi-Agentic — prompts managed manually through each LLM's web interface, with sequential steps handled by the team
- **LLM 1:** Gemini Pro
- **LLM 2:** Claude Opus 4.6

## Workflow — Phase 1 (Semi-Agentic Pipeline)

```
1. Prompt Selection → 30 tasks categorized by difficulty
2. Code Generation → LLM generates Java code from HumanEval prompts
3. Base Testing    → Run dataset-provided tests against generated code
4. Test Improvement → Smell analysis (JNose) + coverage (JaCoCo) → LLM improves tests
5. Manual Assessment → Equivalence partitioning + boundary value analysis
6. Refactoring     → If tests fail, LLM fixes code (feedback loop to step 3)
7. Analysis        → Compare LLM 1 vs LLM 2 results
```

## Workflow — Phase 2 (Integration Testing)

```
1. BookScan Class Generation → LLM creates BookScan integrating tasks #18, #23, #27
   a. Unmodified & Combined prompts → raw HumanEval prompts pasted together
   b. Edited & Combined prompts → refined prompts by the team
2. Integration Testing       → LLM generates integration tests for BookScan
3. Verification              → Run tests, analyze coverage with JaCoCo
4. Prompt Comparison         → Compare results of unmodified vs edited prompts
5. Analysis & Report         → Document findings in final IEEE report (min 8 pages)
```
